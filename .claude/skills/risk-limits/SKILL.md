# 한도와 위반 대응

한도의 단일 출처는 `core/risk/limits.yaml`이고, 판정은 `core/risk/limits.py`가
한다. 이 문서는 해석과 절차만 다룬다. **한도표 수정은 사용자 승인 사항이며
감사로그에 기록된다.**

## DD 트리거는 두 조건을 모두 충족해야 한다

절대 DD(−2.5% / −5% / −7.5%)와 그 알파의 백테스트 DD 분포 분위수(80 / 95 / 99)가
동시에 충족될 때만 조치한다. 변동성이 낮은 전략과 높은 전략에 같은 %를 걸면
전자는 안 걸리고 후자는 상시 걸린다. 절대치를 넘었지만 분포상 정상 범위라면
자본을 삭감하는 대신 레버리지를 낮춰 변동성을 재조정한다.

분위수는 G3–G5에서 계산해 레지스트리에 봉인한 값을 쓴다. 사후 변경은 없다.

## 조건과 무관하게 즉시 중단

원인이 **데이터 오류 또는 코드 버그**로 판정되면 DD 수치와 무관하게 즉시
중단하고 fail-closed를 건다.

## 위반 대응 순서

1. 결정론 엔진이 위반을 반환하면 주문 파일이 만들어지지 않는다(자동).
2. risk-officer가 한도 내에서 감축·손절을 집행한다.
3. 손실이 있었다면 loss-attribution 스킬로 원인을 분류한다.
4. 원인별 재진입 경로: 알파 붕괴·데이터 오류 → G3부터, 코드 버그 → G5부터,
   팩터 충격·실행 비용 → G6부터. 재통과 시 목표 자본의 25%로 복귀한다.
5. 같은 전략이 12개월 내 2회 중단되면 폐기하고 사유를 레지스트리에 남긴다.
