# ADR-0015 — 한도 엔진에서 측정값 부재는 통과가 아니라 차단이다

- Date: 2026-09-22
- Status: accepted
- Context: ADR-0009에서 변동성 목표를 넣을 때, 스냅샷에 `realised_volatility`가 없으면
  차단하도록 만들었다. 이유는 "없는 값을 0으로 읽으면 항상 통과한다"였다. 그 다음에
  같은 질문을 나머지 필드에 던져보지 않았다. 던져보니 **포드 한도 6개가 측정값 없이
  통과하고 있었다.**
- Authorised by: 상시 위임("너가 판단한대로 해, 근데 어떠한 판단에는 항상 근거가
  있어야 해"). 한도 **값**은 바꾸지 않았다 — `limits.yaml`은 손대지 않았다
  (CLAUDE.md 3항). 바뀐 것은 값을 읽는 방식이다.

## 감사 결과

`git grep`으로 `limits.yaml`의 키 19개가 코드에서 읽히는지 세어봤다. 그중 포드 한도의
읽는 방식이 이랬다:

| 필드 | 부재였을 때 이전 동작 | 왜 위험한가 |
| --- | --- | --- |
| `gross` | `.get("gross", 0.0)` → 0배 → 통과 | 노출이 측정되지 않은 북이 무포지션으로 읽힌다 |
| `net` | `.get("net", 0.0)` → 0% → 통과 | 같음 |
| `sector_weights` | `or {}` → 루프가 안 돌아 통과 | 집중도 한도가 아무 북도 검사하지 않았다 |
| `style_betas` | `or {}` → 통과 | 마켓뉴트럴 위임인데 마켓 베타 0.8을 들고 있어도 통과 |
| `liquidation_days` | `.get(..., 0.0)` → 0일 → 통과 | 즉시 청산 가능으로 읽힌다. 가장 관대한 값이다 |
| `drawdown`·`backtest_dd_pct` | `if ... is None: return []` | **손실 중인 포드를 멈추는 한도**가 가장 조용히 통과된다 |

`sector_weights`와 `style_betas`는 계산하는 코드가 애초에 없었다. 즉 그 두 한도는
테이블에 적혀 있었을 뿐이고, 한 번도 아무것도 검사하지 않았다. ADR-0009에 적었던
문장이 그대로 적용된다: **읽는 코드 없이 한도만 넣으면 한도가 있다는 착각만 생긴다.**

## 결정 1 — 부재는 차단한다

`check_pod`의 모든 포드 필드가 `_number()`를 통과해야 한다. `None`·문자열·`NaN`·
`bool`은 측정값이 아니다. `bool`을 따로 막는 이유는 파이썬에서 `True`가 1.0이라
그로스 100%로 읽히기 때문이다. 부재는 `*_UNMEASURED` 코드의 breach가 되고, breach는
신규 주문을 막는다(CLAUDE.md 4항).

**0은 측정값이다.** 평평한 북의 그로스 0, 즉시 청산 가능한 0일, 드로다운 0%는 모두
정상 통과다. 부재와 0을 구별하는 것이 이 ADR의 전부다.

빈 매핑은 경우가 나뉜다. `sector_weights`가 빈 것은 **포지션이 없을 때만** 측정값이다
(평평한 북은 버킷 가중이 없다). 포지션이 있는데 비어 있으면 아무도 계산하지 않은
것이다. `style_betas`는 빈 것이 언제나 부재다 — 측정된 평평한 북은 모든 팩터에 대해
베타 0을 가지며, 베타가 *없는* 것이 아니다.

## 결정 2 — 측정하는 코드를 같은 커밋에 넣는다

차단만 넣으면 파이프라인이 멈추고 아무도 그것을 고칠 수 없다. 그래서
`core/risk/exposure.py`가 포드의 **가중치 이력 하나**에서 스냅샷 전체를 측정한다.

- 노출·버킷 가중·청산일수는 **마지막 행**에서 나온다. 지금 올릴 북을 서술한다.
- 변동성·스타일베타·드로다운은 **이력**에서 나온다. 북이 어떻게 움직이는지를 서술한다.
- 서로 다른 객체에서 뽑으면 한 북이 실현변동성 두 개를 갖게 되고, 그중 하나로 한도를
  통과한다. 이력 하나로 고정한 이유다.
- 변동성은 **다시 구현하지 않았다.** `core/strategies/overlay.realised_volatility`를
  호출한다. 그것이 변동성 오버레이가 스케일하는 계열이고, 같은 수량의 독립 추정값
  두 개는 정확히 ADR-0013에서 연간 세션 수를 측정값으로 만든 이유와 같은 문제다.
  테스트가 스냅샷의 변동성과 손계산이 일치하는지 고정한다.
- 측정 불가는 `None`과 `notes`의 사유로 남는다. 이력이 윈도우보다 짧다, 패널에 거래대금이
  없다, 팩터 파일이 오늘까지 닿지 않는다 — 각각 다른 사유이고 각각 기록된다.

## 결정 3 — 섹터 버킷은 선언하고, GICS라고 부르지 않는다

`core/data/classification.py`의 `SECTORS`가 심볼→버킷을 선언한다. 티커에서 추론하지
않는 이유는 시장과 같다(ADR-0013): 티커는 펀드가 무엇을 들고 있는지 말해주지 않고,
틀린 추측은 집중도 한도를 움직이면서 아무것도 눈에 띄게 하지 않는다.

**이것은 자산군 버킷이고 GICS 섹터가 아니다.** SPY는 모든 섹터를 들고 있으므로 진짜
분해에는 펀드 보유내역이 필요하고 우리는 그것을 받지 않는다. 그래서 SPY는 열한 개
섹터로 쪼개지 않고 `us_equity_broad` 하나로 센다. 한도의 목적("펀드의 5분의 1을 한
곳에 걸지 마라")은 지켜지고, 어디에서도 GICS라고 부르지 않는다. 룩스루는 별 소스와
별 작업이다.

버킷은 의도적으로 거칠다. 안 걸릴 만큼 잘게 쪼갠 버킷은 한도가 없는 것과 같다.

## 스타일베타는 왜 지금 가능해졌는가

ADR-0014가 FF5+모멘텀을 붙였기 때문이다. 팩터 행렬이 없으면 베타는 측정할 수 없고,
이제는 있다. 순서가 이렇게 된 것은 우연이 아니다 — 팩터 소스 없이 `style_beta_abs_max`
를 테이블에 적어둔 것이 이 구멍의 원인이었다.

한국 포드는 팩터 파일이 미국용이므로(ADR-0014) 베타가 측정되지 않고, 따라서
**차단된다.** 불편하지만 맞다: 한국 북의 스타일 노출을 우리는 아직 모른다. 풀려면
한국 팩터 소스가 필요하고 그것은 별 ADR이다.

## 지금 하지 않는 것

- **한도 값은 손대지 않는다.** `limits.yaml`은 이 커밋에서 한 줄도 바뀌지 않았다.
  차단이 늘었다고 기준을 낮추는 것은 CLAUDE.md 3항이 반려하는 변경이다.
- **예외 경로를 만들지 않는다.** "측정할 수 없으면 통과" 플래그는 이 ADR이 막는 것
  자체다.
- **펀드 한도의 부재는 이번에 손대지 않았다.** `var95_1d_max`·`es975_1d_max`·
  `pod_avg_correlation_max`는 읽는 코드가 아예 없다(계산기도 없다). 같은 감사표에
  올라와 있고, 리스크 계산기가 생기는 커밋에서 같은 규칙으로 처리한다. 지금 차단만
  넣으면 측정할 방법 없이 파이프라인이 멈춘다.

## 검증

`tests/limits/test_limits.py`에 부재 차단 케이스를 더해 43건, `tests/risk/test_exposure.py`
21건, `tests/data/test_classification.py` 10건. 중요한 것들: 6개 필드 각각의 부재가
해당 `*_UNMEASURED`로 막히는지, 명시적 `None`도 같은지, `True`가 그로스 1.0으로
읽히지 않는지, **평평한 북의 0들은 전부 통과하는지**(부재와 0의 구별), 포지션이 있는
빈 섹터 매핑은 막히고 평평한 북의 빈 매핑은 통과하는지, 빈 베타 매핑은 언제나 막히는지,
측정기가 만든 스냅샷에는 `*_UNMEASURED`가 하나도 없는지, 거래대금·팩터·짧은 이력이
각각 다른 사유로 `None`이 되는지.

기존 테스트 7건이 깨졌고, **전제를 고쳤다** — 규칙을 되돌리지 않았다. 깨진 이유는
픽스처 스냅샷에 드로다운이 없었던 것이고, 그것이 정확히 이 ADR이 찾아낸 구멍이다.
