# registry/impact

일간 스냅샷의 가격 패널에서 잰 **Amihud(2002) 비유동성 센서스**. 파일 하나가 실행
하나이고 `<run_id>.impact.json`이다. 근거는 ADR-0031.

## 왜 여기 있고 왜 `data/`가 아닌가

`registry/`는 데이터가 아니라 **기록**이다. λ는 가격에서 파생된 숫자이고 원가격은
러너에만 남는다(ADR-0007). 리포트가 `pin`(git SHA + 스냅샷 ID + 시드)을 싣기 때문에
다음 분기에 같은 숫자를 다시 만들 수 있다 — 핀 없는 임팩트 숫자는 재현이 안 된다.

## 읽는 법

- **`measured` / `symbols`가 헤드라인이다.** λ가 없는 종목은 비용이 **미지**인
  종목이고, `book_cost_fraction`은 그런 종목을 들고 있는 북을 **거부한다.** 그래서
  "몇 %를 잴 수 있나"가 이 기계장치를 쓸 수 있는지를 결정한다.
- **`book_round_trip_cost_fraction`이 `null`인 이유는 두 가지이고 서로 다르다.**
  `holdings`와 `book_unmeasured`가 어느 쪽인지 말한다: 들고 있는 게 없어서(플랫 북),
  아니면 들고 있는 것을 못 재서. **플랫 북에 0.0을 쓰지 않는다** — 산술로는 맞지만
  "이 북은 거래가 공짜"로 읽힌다.
- **`conservatism` 문장을 숫자와 같이 읽는다.** 크로싱마다 **종단 변위**를 부과하고
  (실제 주문은 평균 변위, 절반쯤) λ가 **선형**인데 실제 임팩트는 오목하다. 둘 다
  비용을 높게 캐패시티를 낮게 민다. **상한이고 체결 예측이 아니다.**
- **`capacity_unmeasured`가 비어 있지 않은 것이 정상이다.** 비용 기반 캐패시티는
  전략의 그로스 엣지가 필요하고, 아직 게이트를 통과한 알파가 없다.
- `unmeasurable_reasons`는 사유별로 묶여 있다. 같은 사유 100건은 문제 하나다.

## 여기 없는 것

**실현 슬리피지(TCA).** 체결이 있어야 하고 없다. **그때 이 λ의 예측력을 검증할 수
있고, 검증 전까지 이 숫자는 추정이라고 부른다.** 집행되는 캐패시티 상한은 여전히
참여율 기반(`core/risk/capacity.py`, ADR-0026)이고 이 디렉터리의 숫자는 **소견**이다.

생성: `uv run python -m scripts.impact_report` (일간 `data-snapshot` 워크플로).
