# registry/stress/

역사 시나리오 스트레스 리포트가 쌓입니다. `data-snapshot` 워크플로가 주간으로
(토요일) 돌리고, `scripts/stress_report.py`가 씁니다 (ADR-0027).

- `<run_id>.stress.json` — 한 번의 실행. `run_id`는 git SHA + 스냅샷 ID + 시드이므로
  같은 파일 이름이 두 번 나오면 같은 코드·같은 데이터·같은 시드입니다.

## 무엇이 들어 있고, 왜 그것만 들어 있는가

- **시나리오는 날짜만 정의돼 있습니다.** 크기는 매번 팩터 파일에서 계산합니다.
  `core/risk/stress.py`의 `SCENARIOS`에 손실률이 적혀 있지 않은 것이 의도입니다 —
  타이핑한 위기 수익률은 아무도 검산하지 못합니다(CLAUDE.md 2항).
- **팩터 파일 자체는 커밋되지 않습니다.** 켄 프렌치 라이브러리는 연구에 무료지만
  재배포를 허락하지 않으므로 가격과 같은 처리입니다(ADR-0007). 리포트가 파일의
  **다이제스트와 기간**을 들고 있고, 그것이 재현의 근거입니다.
- **`unmeasured`가 비어 있지 않은 리포트는 부분적인 리포트입니다.** 팩터 파일이
  못 덮는 창은 0이 아니라 측정 불가로 기록됩니다. 11개 중 2개만 평가된 리포트를
  "이상 없음"으로 읽으면 안 되고, 그래서 평가하지 못한 창도 한 줄씩 나옵니다.
- **`findings`는 소견이고 집행이 아닙니다.** 가상 손실은 실현 낙폭이 아니므로
  `Breach`가 아닙니다. 각 줄은 시나리오가 기존 `pod.drawdown` 사다리의 어느 칸에
  닿는지만 말합니다. `limits.yaml`에 `stress:` 블록을 만드는 것은 소유자 승인
  사항입니다(CLAUDE.md 3항).

## 지금 북은 스모크 북입니다

`book` 필드가 매번 그렇게 말합니다. 이 데스크에 포지션이 없고, 리포에 있는 유일한
북은 게이트 경로를 증명하려고 돌리는 횡단면 모멘텀입니다. **실제 북이 생길 때까지
안 돌리는 쪽을 택하지 않았습니다** — 그러면 배관이 처음 필요한 날에 처음 돌게 됩니다.

## 손실은 낙관적인 절반입니다

팩터 시나리오는 오늘의 베타에 선형이고, 팩터가 설명하는 부분만 설명합니다. 두 오차가
모두 손실을 작아 보이게 하므로 `residual_band`가 따로 있습니다. `factor_loss`만
인용하는 인용은 틀린 인용입니다. 밴드는 √기간이라 위기의 잔차 군집을 무시하고,
그쪽으로도 좁습니다.
